¿Qué infraestructura hace posible abrir una página web?

Antes de trabajar con máquinas virtuales y plataformas cloud, necesitamos reconocer la infraestructura física, los servicios y los protocolos que intervienen cuando un cliente solicita un recurso en Internet.

Pregunta detonante: cuando escribes una URL, ¿qué equipos y servicios trabajan antes de que aparezca la página?

Infraestructura: los elementos físicos

Son equipos y medios que conectan dispositivos, transportan tráfico, aplican controles o ejecutan sistemas. Las fotografías son ejemplos reales de fabricantes; no significan que una arquitectura deba usar esas marcas.

ACCESS POINT

HPE Aruba AP-635

Función: conecta dispositivos inalámbricos a la red local.

No es un router: normalmente no decide la ruta entre redes; da acceso Wi‑Fi a una LAN.

SWITCH

Cisco Catalyst 9300

Función: interconecta equipos dentro de una LAN y reenvía tramas hacia el puerto adecuado.

Diferencia clave: el switch conecta principalmente dentro de una red; el router conecta redes diferentes.

ROUTER / GATEWAY

Cisco ISR 1100

Función: conecta la red local con otras redes y decide por dónde reenviar paquetes.

Gateway: es el punto de salida que usa el cliente para llegar fuera de su propia red.

ROUTER ISP / CORE

Juniper MX

Función: enruta grandes volúmenes de tráfico entre redes de proveedores, empresas y centros de datos.

Diferencia con el router del cliente: la función básica es la misma, pero cambia enormemente la escala, capacidad y redundancia.

Referencia oficial

SWITCH DE DATA CENTER

Cisco Nexus 9300

Función: conecta servidores y equipos de red dentro de un centro de datos con enlaces de alta capacidad.

Diferencia con un switch de acceso: ambos conmutan tráfico, pero el de data center prioriza densidad, velocidad y baja latencia.

Referencia Cisco Nexus
🧱
FIREWALL

Fortinet FortiGate 90G

Función: permite o bloquea tráfico según reglas de seguridad.

No es un router “normal”: puede enrutar, pero su función pedagógica aquí es controlar qué conexiones están autorizadas.

Referencia oficial
⚖
ADC / LOAD BALANCER

F5 BIG-IP rSeries

Función: distribuye solicitudes entre servidores disponibles y ayuda a mantener el servicio disponible.

Diferencia con el router: el router busca una red destino; el balanceador selecciona un servidor que atenderá un servicio.

Referencia oficial
▥
SERVIDOR

Dell PowerEdge

Función: aporta CPU, memoria y red para ejecutar sistema operativo, servidor web, aplicaciones u otros servicios.

No es “la aplicación”: el servidor es infraestructura; la aplicación es software que corre sobre él.

Referencia oficial

ALMACENAMIENTO

NetApp AFF

Función: ofrece capacidad persistente para archivos, bloques u otros datos.

Diferencia con un servidor: el servidor ejecuta cómputo; el storage se especializa en conservar y entregar datos.

Diferencias que deben quedar claras

Comparación
Componente A
Componente B
Switch vs Router
Switch: conecta dispositivos dentro de una LAN.
Router: conecta redes diferentes y elige la siguiente ruta.
Router vs Firewall
Router: decide hacia dónde reenviar.
Firewall: decide si una conexión está permitida.
Router vs Load Balancer
Router: busca una red o siguiente salto.
Balanceador: selecciona qué servidor atenderá el servicio.
Servidor vs Storage
Servidor: ejecuta procesos y aplicaciones.
Storage: conserva y entrega datos de forma persistente.

Servicios: funciones que se ejecutan sobre la infraestructura

Un servicio no necesariamente corresponde a una caja física específica. Puede ejecutarse en uno o varios servidores, appliances o máquinas virtuales.

RELACIÓN

Infraestructura ≠ servicio

Un servidor físico Dell puede ejecutar NGINX; NGINX puede reenviar hacia una aplicación Django; Django puede consultar PostgreSQL. Son funciones diferentes aunque puedan convivir en la misma máquina.

Modelo mental:
hardware → sistema operativo → servicio → aplicación → datos

Protocolos: reglas para que los componentes se entiendan

No necesitamos dominar todavía todos sus campos. Para el taller basta con saber qué problema resuelve cada uno.

Nota actual: HTTP/1.1 y HTTP/2 suelen utilizar TCP. HTTP/3 utiliza QUIC sobre UDP. En el taller trabajaremos con HTTPS sobre TCP porque es una introducción a TCP/IP y al flujo de infraestructura.

Qué debes observar

¿El retorno usa exactamente los mismos equipos?

No necesariamente. En Internet puede existir enrutamiento asimétrico: la respuesta puede tomar otra ruta física. Para el taller representaremos el retorno de forma simplificada para concentrarnos en la función de cada estación.

Regla de oro: ningún grupo resuelve lo que corresponde a otro componente.

Secuencia del estudiante-mensaje

Lleva el sobre a la estación indicada.
Entrega únicamente la información que lleva el mensaje.
Escucha qué hizo el componente y qué resultado devuelve.
Evalúa si la decisión es coherente con la información mostrada por la estación.
Registra y continúa. Si la comunicación termina, anota la causa.
