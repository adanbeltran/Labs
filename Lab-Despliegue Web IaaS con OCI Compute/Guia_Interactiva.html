La analogía tiene límites: la IP pública no es una segunda dirección privada del servidor; OCI realiza la asignación y traducción correspondiente en la infraestructura. El puerto identifica el servicio de destino, no una puerta física. Un Internet Gateway tampoco es un firewall.

3. Direcciones IP, CIDR y puertos

¿Cuántas direcciones representa un CIDR?

Piensa en una avenida: el prefijo indica qué parte identifica el barrio; los bits restantes permiten identificar direcciones dentro de él.

En OCI, la subred reserva tres IP: dirección de red, primer host para la puerta de enlace virtual y última dirección. No confundir con la regla simplificada de «menos dos» utilizada en algunas redes tradicionales.

Una IP puede tener muchas puertas

🚪
:22

SSH

🚪
:80

HTTP

🔒
:443

HTTPS

Ejemplo: 203.0.113.10:80 identifica una IP pública y el servicio web HTTP. El puerto de origen del navegador suele ser efímero, por ejemplo 52000.

El CIDR 0.0.0.0/0 abarca todas las direcciones IPv4. En una regla ingress indica cualquier origen; en una ruta por defecto indica el destino menos específico, sujeto a rutas más específicas.

5. ¿Por qué no responde?

🛂

La regla no deja entrar

La solicitud TCP al puerto 443 no coincide con ingress 22 ni 80. La red la descarta, aunque el servidor hipotéticamente escuchara.

🗺️

La ruta no existe

Sin la ruta por defecto hacia el gateway, se rompe la conectividad pública requerida para el intercambio con Internet.

📬

No tiene IP pública

Desde Internet no basta con escribir la dirección privada 10.0.0.10. El acceso directo requiere un destino público válido.

🚪

La aplicación está cerrada

Una regla abierta no inicia automáticamente Nginx, Apache ni SSH. El sistema operativo y el proceso deben aceptar conexiones.

↩️

La respuesta puede volver

Una ingress stateful que permite la conexión TCP también permite el tráfico de respuesta asociado, sin exigir una regla egress específica.

🔐

Permitir tráfico no autentica

El puerto 22 abierto no significa acceso SSH autorizado. Siguen siendo necesarias credenciales o claves válidas.

¿Por qué el taller abre SSH al mundo y cómo se haría mejor?

El taller usa el origen 0.0.0.0/0 para los puertos 22 y 80, por facilidad de práctica. En producción es preferible restringir SSH a IP de administración conocidas o acceder con OCI Bastion; para una web pública conviene HTTPS por TCP/443, con terminación TLS y controles adecuados.

¿Qué cambia si una regla es stateless?

Una regla stateless no mantiene seguimiento de la conexión. En ese caso el retorno requiere reglas explícitas que coincidan con los puertos y direcciones de respuesta. El taller indica dejar Stateless desmarcado, por lo que el simulador reproduce comportamiento stateful.

¿Qué diferencia hay entre una Security List y un NSG?

La Security List se asocia a la subred y afecta las interfaces de las máquinas incluidas. Un Network Security Group (NSG) aplica reglas a un conjunto seleccionado de VNIC o recursos. El taller utiliza la lista de seguridad predeterminada; no configura NSG.

¿HTTP y HTTPS responden igual?

No. HTTP suele utilizar TCP/80 y transmite datos de aplicación sin cifrado TLS. HTTPS suele utilizar TCP/443 y añade TLS. En este taller se autoriza TCP/80, pero no se crea una regla nueva para TCP/443.
